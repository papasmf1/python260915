# PRD - Todo List 웹사이트

## 1. 문서 목적
HTML5, CSS3, JavaScript로 제작하는 Todo List 웹사이트의 제품 요구사항을 정의한다. 현재 단계에서는 기능을 구현하지 않고, 구현에 필요한 요구사항만 정리한다.

## 2. 제품 개요
- **제품명**: Todo List
- **목표**: 사용자가 할 일을 빠르게 추가하고, 상태를 관리하며, 완료된 일을 구분해서 볼 수 있는 웹사이트를 제공한다.
- **대상 사용자**: 개인 일정과 간단한 업무를 브라우저에서 관리하려는 사용자
- **플랫폼**: 데스크톱 및 모바일 웹 브라우저
- **핵심 가치**: 빠른 입력, 명확한 상태 확인, 간결한 관리 경험

## 3. 핵심 사용자 시나리오
1. 사용자가 입력창에 할 일을 작성한다.
2. 사용자가 추가 동작을 실행하면 할 일이 목록에 표시된다.
3. 사용자가 할 일을 완료 처리하거나 다시 미완료 상태로 되돌린다.
4. 사용자가 필요하지 않은 할 일을 삭제한다.
5. 사용자가 전체, 진행 중, 완료 상태별로 목록을 확인한다.
6. 사용자가 페이지를 다시 열어도 기존 할 일 목록을 확인한다.

## 4. 기능 요구사항

### 4.1 할 일 추가
- 입력창에 할 일 내용을 입력할 수 있어야 한다.
- 추가 버튼 또는 Enter 키로 할 일을 추가할 수 있어야 한다.
- 내용이 비어 있거나 공백만 있는 경우 추가하지 않고 사용자에게 안내한다.
- 새 할 일은 기본적으로 미완료 상태여야 한다.

### 4.2 할 일 목록 표시
- 각 항목에 할 일 내용, 완료 상태 컨트롤, 삭제 컨트롤을 표시한다.
- 미완료 항목과 완료 항목을 시각적으로 구분한다.
- 할 일이 없을 때 빈 목록 상태를 표시한다.
- 전체 항목 수와 완료되지 않은 항목 수를 확인할 수 있어야 한다.

### 4.3 완료 상태 변경
- 사용자는 체크박스 또는 동등한 컨트롤로 완료 상태를 변경할 수 있어야 한다.
- 완료된 항목은 취소선 등으로 상태 변화를 인지할 수 있어야 한다.
- 완료 상태를 다시 미완료로 되돌릴 수 있어야 한다.

### 4.4 할 일 삭제
- 각 할 일을 개별적으로 삭제할 수 있어야 한다.
- 삭제 후 목록과 항목 수가 즉시 갱신되어야 한다.

### 4.5 목록 필터
- 전체 목록을 볼 수 있어야 한다.
- 진행 중인 할 일만 볼 수 있어야 한다.
- 완료된 할 일만 볼 수 있어야 한다.
- 현재 선택된 필터를 사용자가 쉽게 인지할 수 있어야 한다.

### 4.6 데이터 보존
- 할 일 데이터는 브라우저의 로컬 저장소에 보존한다.
- 페이지를 새로 고침하거나 다시 방문해도 저장된 목록을 복원한다.
- 저장된 데이터가 없거나 손상된 경우 빈 목록으로 안전하게 시작한다.

## 5. 비기능 요구사항
- HTML5 시맨틱 요소를 사용한다.
- CSS3로 반응형 레이아웃을 제공한다.
- 외부 프레임워크 없이 순수 JavaScript로 구현한다.
- 키보드만으로 주요 기능을 사용할 수 있어야 한다.
- 버튼과 입력 요소에 명확한 접근성 이름을 제공한다.
- 모바일 화면에서도 가로 스크롤 없이 사용할 수 있어야 한다.
- 사용자 입력을 화면에 표시할 때 안전하게 처리한다.

## 6. 범위 제외
- 회원가입, 로그인, 서버 저장소
- 여러 사용자 간 목록 공유
- 마감일, 우선순위, 태그, 알림 기능
- 별도의 백엔드 API
- 이번 단계의 HTML, CSS, JavaScript 기능 구현

## 7. 성공 기준
- 사용자가 새 할 일을 추가할 수 있다.
- 사용자가 완료, 필터, 삭제 동작을 이해하고 수행할 수 있다.
- 새로 고침 후에도 목록이 유지된다.
- 데스크톱과 모바일에서 주요 화면과 동작이 깨지지 않는다.
- 키보드와 보조기술 사용자를 고려한 기본 접근성 요건을 충족한다.
